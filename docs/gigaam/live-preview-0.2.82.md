# Постепенный показ GigaAM и пунктуация редактора — 0.2.82

Две независимые опции, обе по умолчанию выключены:

- Настройки → Речь и команды → GigaAM → «Текст во время записи».
- Настройки → Речь и команды → Пунктуация голосового ввода →
  «Другие знаки в редакторе заметок». Требуется включённая дополнительная
  обработка и совместимая модель RUPunct.

Настройки сохраняются отдельно и входят в переносимые настройки.

## Предварительный текст

Используется текущая CTC-модель без изменения весов и формата ONNX.
Это периодическое распознавание накопленного аудио, а не модель с кешируемым
потоковым состоянием. Первый снимок — через 800 мс, последующие проходы
последовательны с интервалом 1–4 секунды в зависимости от времени обработки.
Очередь запросов не накапливается. Долгие записи используют прежние границы
сегментов: готовые сегменты кешируются только внутри одной записи, пересчитывается
текущий хвост до 25 секунд. Предварительный проход ограничен 1,5 секундами;
при ошибке предварительный показ прекращается, полное распознавание остаётся.

Микрофон продолжает записывать исходный WAV. Снимки читают только завершённые
PCM16-отсчёты, не используют ещё не обновлённый WAV-заголовок. Предварительный
проход использует исходный звук; выбранная предобработка применяется к полной
записи после остановки, поэтому текст может уточняться.

Состояние предварительного текста отделено от recognizedText, результата
диктовки и выполнения команд. Обновление заменяет прежний показ целиком,
не дописывает накопленные гипотезы. Во всех вкладках и редакторе используется
карточка с прокруткой к новым словам. Текст в ней не сохраняется в заметку.

После отпускания кнопки отменяется текущий предварительный проход, ожидается
его завершение, затем распознаётся полный WAV обычным способом. Новый RunOptions
не наследует флаг terminate. Пунктуация вызывается только для окончательного текста.
Редактор получает один результат и сохраняет прежнее единое действие отмены.
При уходе в фон/отмене диктовки предварительная задача отменяется, сессия
освобождается с соблюдением блокировки native runtime.

## Дополнительные знаки в редакторе

Используются существующие 33 класса RUPunct, три варианта регистра агрегируются
в вероятность знака. Запятые — прежний порог 0,55; остальные — 0,65.
Поддержаны точка, вопросительный/восклицательный знак, двоеточие, точка с
запятой, тире, многоточие и `?!`. Дефис внутри слов не генерируется.
Регистр исходных названий сохраняется; заглавная буква добавляется в начале
предложения, без перевода целых слов в верхний регистр.

Текст строится из исходных слов и промежутков, не из строк токенизатора.
Существующие точки, кавычки, адреса, ссылки, десятичные числа, время и переносы
строк сохраняются. Меняются только подходящие промежутки между словами;
числа подряд не разделяются новыми знаками. В конец не добавляются запятая,
тире или двоеточие. Команды продолжают использовать прежний режим запятых.

## Проверки и ограничения

- Девять сохранённых аудио прогнаны на возрастающих префиксах опубликованной
  GigaAM v3 INT8. Каждый полный результат совпал с исходным контрольным результатом,
  включая намеренные повторы, после принудительного terminate промежуточного прохода.
  Это desktop ONNX Runtime, не замер задержек Android UI.
- RUPunct INT8 с неизменным SHA-256 проверена на 18 фиксированных текстах через
  токенизатор приложения и производственный код выбора знаков/сборки текста.
  Проверено сохранение всех слов и числовых/адресных значений.
- На вопросах «почему дверь осталась открытой», «как пройти к ближайшей станции»,
  «сколько времени осталось до отправления» получен вопросительный знак.
  «Когда начнётся встреча» осталась без вопросительного знака. Два вопроса в одной
  строке модель иногда объединяет запятой и завершает точкой. Восклицания и
  границы нескольких предложений восстанавливаются не всегда верно.
- Дополнительные знаки — вариант для проверки пользователем, не гарантия
  грамматически точного оформления. Голос, интонация и паузы не передаются RUPunct.

Результаты: `preview-audit-0.2.82.json`, `punctuation-audit-0.2.82.json`.
Новые веса не обучались, пороги не подстраивались под проверочные предложения.
Производственные проверки покрывают CTC-повторы, прерывание (нативный replay),
границы сегментов, сохранение ссылок/чисел/кавычек, отсутствие двойных знаков
и перенос обеих настроек в резервную копию.

Описание меток: [RUPunct Small](https://huggingface.co/RUPunct/RUPunct_small).

## Установка и проверка на телефоне

Подписанная release-сборка и lintVitalRelease прошли; основные JVM-тесты прошли,
отдельная optional-оценка RUPunct также прошла проверки сохранения слов.
0.2.82 установлена обычным установщиком Android, проверены versionCode 105 и
versionName 0.2.82. На устройстве видны обе настройки и выбранная GigaAM v3 INT8.
Предварительный показ был временно включён для контрольной записи; пользователь
подтвердил: «все хорошо показывает». Итоговый текст показан в поле подтверждения.
Затем предварительный показ выключен обратно и состояние проверено в настройках.
Пункт «Другие знаки в редакторе заметок» доступен при выбранной RUPunct;
последнее наблюдаемое состояние на телефоне — включён. При проверке этот пункт
не переключался. Оба значения по умолчанию в новой установке остаются false.
