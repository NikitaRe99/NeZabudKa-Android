# Настройки моделей 0.2.63–0.2.64

0.2.63 установлена на Vivo. Единые окна выбора моделей включают скачивание, установленный каталог и импорт. Для пунктуации поддерживаются ONNX-файлы с входами input_ids/attention_mask/token_type_ids, форматом выходных меток и токенизатором RUPunct. Проверка при импорте выполняет пробный запуск, однако семантическую совместимость словаря/порядка меток пользовательской модели невозможно гарантировать одной проверкой формы тензоров.

В 0.2.63 облачные ключи читаются из существующего защищённого хранилища в скрытые поля, сохраняются без очистки интерфейса и могут отображаться глазком. Значения не добавляются в переносимую резервную копию или поток диагностических состояний. VK разрешает сохранить токен до заполнения endpoint; для распознавания HTTPS endpoint по-прежнему обязателен. Справка находится напротив строки требований внутри карточки; ссылки и закрытие находятся в одном ряду.

Изменения исходников для 0.2.64:

- Перед импортом показан формат: GGML .bin для Whisper; совместимый ONNX .onnx для NLU; ONNX с токенизатором и метками RUPunct для пунктуации.
- Дополнительная пунктуация включается отдельной галочкой. Отключение сохраняет выбранный файл; выбор, успешный импорт или начало скачивания модели включают обработку. В окне моделей больше нет пункта «Как распознал Whisper / STT».
- Удержание Whisper учитывает видимость всех Activity приложения. При уходе в фон модель освобождается под mutex после текущей транскрипции, без её отмены. Перед освобождением повторно проверяется видимость: возвращение пользователя отменяет отложенное освобождение. Транскрипция, начавшаяся уже в фоне после остановки записи, освобождает модель сразу в finally, а не после обычного таймера. Пересоздание Activity при изменении конфигурации не считается уходом в фон.

Проверки 0.2.63: компиляция, release build/lint, 15 unit-тестов; на телефоне проверены расположение Whisper выше NLU, окно NLU, окно пунктуации с импортом, наличие глазка и требований VK. Полный визуальный осмотр облачной карточки и восстановление выбранного движка прерваны: автоматическая проверка разрешений не смогла выполнить проверку из-за лимита использования. После диагностического переключения на телефоне остаётся выбран VK; пользователю сообщено, что нужно вернуть Whisper.

0.2.64 ещё не собрана, не установлена и не проверена выполнением тестов. Доступ к командам, требующим выхода за файловую песочницу (кэш Gradle/ADB), остаётся заблокирован указанным сбоем проверки разрешений. Проверен только diff на ошибки пробелов. Следующие обязательные шаги: компиляция/unit-тесты, проверка сценариев свернуть/вернуться во время и после распознавания, signed release build с исключением неутверждённого дизайна будильника, установка и проверка окна импорта/галочки пунктуации.

## Обновление после восстановления доступа

Предыдущий абзац описывает остановленную проверку до восстановления доступа. Теперь 0.2.64 скомпилирована, release build/lint завершены, 333 unit-теста прошли (два необязательных пропущены), подписанная версия установлена на Vivo.

В эту же сборку включены новые настройки напоминаний: карточка выбора «Уведомлением/Будильником» и общей вибрации; обычные уведомления скрыты в режиме будильника, параметры будильника и повторов скрыты в обычном режиме. Мелодия включена в карточку будильника. Разрешения окна показываются только при соответствующем режиме; общие разрешения и фоновые настройки имеют короткие понятные названия и статусы. Удалена подсказка про содержимое уведомлений на экране блокировки. Видимость разделов при обоих режимах покрыта SettingsCatalogTest.

На телефоне проверен текущий режим будильника: объединённая карточка и повторы присутствуют, обычная карточка уведомлений отсутствует; просмотрены сокращённые разрешения. Режим исходно был «Будильником» и не был изменён. Полное ручное переключение обоих режимов и измерение освобождения памяти Whisper во время/после живого распознавания ещё не подтверждены.
