# Оптимизации энергии и плавности в 0.2.87

Проверено 23 октября 2026 года. Основание: [аудит 0.2.86](energy-0.2.86.md). Изменения перечислены в [описании версии](../releases/0.2.87.md).

## Что изменено

| Область | Изменение |
| --- | --- |
| Предварительный текст GigaAM | PCM читается и переводится в float только для добавившейся части WAV. Снимок для распознавания остаётся независимым массивом. Ограничение длины предпросмотра сохранено. |
| Модели | Сессии GigaAM и RUPunct переиспользуются до минуты простоя в открытом приложении; освобождаются в фоне и при нехватке памяти. Словарь и конфигурация RUPunct читаются один раз. При смене файла сессия пересоздаётся. |
| Вычисления ONNX | Явно отключено активное ожидание intra/inter-op потоков. Количество потоков, модели, декодирование и параметры качества сохранены. |
| Виджеты | Изменения базы объединяются за 300 мс. Неизменившаяся оболочка повторно не отправляется; коллекция обновляется отдельно. Общие запросы переиспользуются между экземплярами. Отключённая функция не загружает строки базы. |
| Периодические обновления | Заметки обновляются по событиям. У напоминаний сохранены события, смена дня и резервное обновление раз в шесть часов. |
| Резервные копии | Вместо загрузки таблиц в наблюдателях и повторного чтения используется уведомление об изменении и один согласованный снимок в транзакции. Файл записывается после завершения транзакции. Одинаковая существующая копия не перезаписывается. Пауза 1,2 секунды, проверка записи и предыдущая копия сохранены. |
| Обновления | Автоматическая проверка раз в 12 часов, ручная — сразу. HTTP-кеш с условной проверкой страниц; APK в этот кеш не записывается. История пропущенных исправлений сохранена. Проверенная ошибка совместимости не запускает повторные загрузки. |
| Корзина | Плановая очистка имеет гибкое окно и ограничение по заряду; ручная не задерживается. |
| Заметки | При пересчёте запроса и порядка прежний список остаётся на экране до готовности нового. Сортировка переиспользуется при поиске и смене папки. |
| Напоминания | Сортировка и фильтрация выполняются на рабочем потоке. Поиск и обновление времени не повторяют сортировку неизменившейся базы. |

## Сохранение качества

Итоговое распознавание по-прежнему читает полный остановленный WAV. Сегментация, предобработка, частота дискретизации, число вычислительных потоков и настройки точности не сокращены. Промежуточный текст не подменяет итоговый. Порог обнаружения речи и отсечение тишины не ужесточались.

Проверки:

- На компьютере: GigaAM v1, v2 и v3 INT8, по девять записей для каждой модели. При переключении активного ожидания потоков и при повторном использовании сессии выходные токены и длины совпали точно.
- На Samsung S9 / Android 10: итоговый текст GigaAM v3 на трёх WAV совпал с прежним вычислением при активном ожидании. Совпадение проверено повторно на сохранённой сессии и после явного освобождения модели.
- На Samsung: три текста, обычная и полная пунктуация RUPunct; результат совпал между холодной, повторно используемой и освобождённой сессией.
- JVM-проверки PCM: побитовое совпадение float-сэмплов на растущей записи, неполный последний PCM-сэмпл, ограничение длины, сброс и независимость предыдущего снимка.

Это проверка отсутствия изменений на выбранных примерах, а не гарантия одинакового результата для любой записи и любого устройства.

## Плавность

На Samsung выполнена прокрутка отдельной debug-сборки с 300 временными заметками и 240 напоминаниями. Пользовательская база основного приложения не менялась. Для каждой страницы выполнено шесть жестов прокрутки; данные собраны через `Window.OnFrameMetricsAvailableListener`.

| Экран | Измерено кадров | Медиана TOTAL_DURATION | 95-й процентиль | Кадров дольше 16,67 мс |
| --- | ---: | ---: | ---: | ---: |
| Заметки | 297 | 11,95 мс | 23,91 мс | 60 |
| Напоминания | 350 | 11,00 мс | 27,54 мс | 88 |

Это длительность подготовки кадров в debug-сборке, не полный показатель задержки касания или точная частота вывода кадров. Сопоставимого замера предыдущей сборки не проводилось, поэтому процент ускорения не заявляется. Длинные кадры ещё встречаются; стабильные 60 кадров/с на всех сценариях не подтверждены. Устранены конкретные лишние операции и исчезновение карточек при пересчёте.

## Регрессии и ограничения

- JVM: 401 тест, ошибок и падений нет, шесть пропущены существующими условиями набора. Android lint прошёл.
- На Samsung проверены согласованный снимок резервной копии с двумя связями папок, повтором и состоянием выполнения напоминания; четыре проверки данных виджетов; нативные коллекции виджетов, независимость экземпляров, темы, изменение размера и действия.
- В существующей проверке виджетов вызов очистки кеша UiAutomation сделан необязательным: этого API нет на Android 10. Это исправление теста.
- Кеш PCM и краткое удержание сессий требуют дополнительной памяти во время работы. Кеш PCM сбрасывается при остановке и отмене записи; сессии освобождаются при уходе в фон, по таймеру и при нехватке памяти.
- Автоматический подбор числа потоков не заменён произвольным «экономичным» значением: меньше потоков не обязательно означает меньше энергии. Точные напоминания не ослаблены.
- Процент экономии батареи не измерен. Для него нужен сравнительный разряд без USB и длительный тест с выключенным экраном. Уменьшение повторной работы подтверждено кодом и проверками, но не заменяет такое измерение.
